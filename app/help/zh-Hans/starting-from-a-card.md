## 会列出你的工作的卡片

新聊天打开时会显示几张卡片。需要你提供信息的卡片（工单、pull request、分支）会打开一个列表，列出你自己最近的内容：你查看过或分配给你的问题、等你审阅的 pull request、你最近的、还没有 pull request 的分支。点击一行，助手就开始工作。在输入框中输入可以筛选列表或搜索。

输入框始终可用。和以前一样，粘贴链接或输入编号后按 Enter 即可；列表只是一条捷径。

有些卡片需要不止一项信息，比如一个 story 和要运行的平台。填好各个字段后点击**继续**。

卡片上可能带有一个小的计数，比如**2 个待审阅**或**1 个失败**：这是正在等你处理的工作，来自这张卡片打开时显示的同一个列表。

## 列表从哪里来

Portal 使用你自己的连接器设置读取列表，也就是你的助手所用的那些设置。关闭的连接器不会列出任何内容：卡片会告诉你需要在[连接器](#/help/concepts)中设置哪一个，输入框仍然可用。

无论连接器用哪个账号登录，列表始终是你自己的。很多连接器使用共享账号登录，而共享账号做过的事并不是你做过的事，所以 Portal 会按你的 Portal 用户名查找你。这时不提供**最近查看的**：那份浏览记录属于共享账号。

如果在那个系统中找不到你的用户名，就不会列出你最近的工作，输入框会说明这一点。输入文字仍然可以搜索。

你选择的内容只会以编号或链接的形式发送。标题和摘要只显示给你看，不会发送给助手。

## 用于 pull request 的分支

创建 pull request 时，列表最前面是这个助手的工作区中已检出、并且有自己的提交或更改的分支：也就是助手完成、但工作区之外还不知道的工作。

接下来是你自己最近的分支：你最近在自己参与的仓库中创建或推送过的分支，还没有 pull request 的排在前面。一分钟前刚推送的分支也会出现。

选中一个分支后，**Merge into** 会自动填入该仓库的默认分支。如果 pull request 要合并到别的分支，改掉它即可。

## 输入时引用内容

在消息输入框中输入 `#`，可以在自己写消息时使用同样的列表：最近的 Jira 问题、pull request 和 Confluence 页面。用方向键和 Enter 插入其中一项，或者继续输入以忽略列表。Enter 仍然会发送你的消息。

## 以前用过的值

每张卡片会在这个浏览器中记住你最近给它的几个值，并显示在**以前用过的**下面。
