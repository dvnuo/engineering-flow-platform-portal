## 什么时候需要

只有当你的网络必须通过代理才能访问互联网时才需要。如果助手不用代理也能正常工作，就保持关闭。

如果需要代理，管理员会告诉你 URL。大多数成员从不需要动这个页面：除非你选择「自定义」，否则「代理」连接器会跟随管理员的「默认连接器」。

## 多个代理

有的网络不止一个出口：一个代理通往互联网，另一个通往合作伙伴网络，而助手能直接访问的数据库则完全不需要代理。「代理」连接器按名称列出每个代理，并用一张表格说明每个连接器经过哪一个。

- **代理**：每个代理一张卡片。**名称**是下拉框中显示的名字（字母、数字、`-` 和 `_`）；**代理 URL** 按网络团队给出的原样填写，如 `http://proxy.example.com:3128` 或 `https://...`；**登录信息**可选；**不使用代理的主机**列出不应经过这个代理的主机，用逗号分隔，如 `localhost,.svc.cluster.local`。
- **默认代理**：助手环境中设置的代理。只读取环境变量的工具（AWS CLI、`kubectl`、`gh`、`git`）始终使用它，所有保持*默认*的连接器也是如此。
- **每个连接器使用哪个代理**：为每个连接器选择一个代理，或选择*无（直连）*。选*无*时，助手会直接连接该服务，不管环境变量如何设置。AWS 和 GitHub 只显示*默认*：目前还无法为它们的工具单独指定代理。

卡片上的**测试这个代理**用于检查代理本身是否有响应。Jira、Confluence、GitHub、Jenkins、Nexus、Splunk 和 PostgreSQL 的测试按钮（如「测试 Jira」）会沿你在这里选择的路线探测，所以分配错误会直接显示在受影响的连接器上。「测试模型提供方」和「测试 BrowserStack」仍从 Portal 本身发出；为这两个连接器分配的代理在助手中生效。

**不使用代理的主机**中的条目按 `NO_PROXY` 的惯常规则解读：名称覆盖该主机及其子域名；名称前加一个点（`.corp.example`）则只覆盖子域名；IP 地址或 CIDR 网段（`10.0.0.0/8`）覆盖其中的地址。

## 只有一个代理

如果你的网络只有一个代理，就添加一张卡片，让它作为默认代理，表格全部保持*默认*。这与以前只填一个 URL 的效果完全相同。
