## 整体流程

1. 业务分析师（BA）在 Jira 中完成一条需求，并把它移到团队约定的状态，例如 **Ready for Test**。
2. 由这次状态变更触发的委派会让助手起草场景：按组整理的 Scenario Outline 及其 Examples 表，覆盖正向和反向用例，每个 Examples 行都带有预期结果。
3. 你在任务页面上批准这些场景（一张审阅卡片：勾选要保留的场景，说明要修改什么）。
4. 你在自己的电脑上，用一台 BrowserStack 真机一次录完一个场景，每个平台录一次。助手会提出如何把录制拆分成可复用的片段（登录、跳过介绍页、选择货币），由你确认拆分方案。然后你在同一台设备上回放这些片段，亲眼确认它们能正常运行，之后才会生成脚本。
5. 助手把批准的场景和你的片段转换成一个普通的 Python 测试项目（你批准的 Gherkin、对应的步骤定义，以及写成函数的片段，其中每一行录制的代码都标有 `# recorded:`），提交到团队的测试仓库，并让 Jenkins 流水线在一台设备上为每个场景运行一行 Examples。然后由你批准。
6. 完整运行通过同一条流水线并行进行，并在构建页面上发布 Cucumber 报告。每个场景最后都有结果、截图和该次会话的视频；失败会被归入脚本漂移、产品缺陷、基础设施或测试数据。这些测试不依赖 EFP：任何拥有该仓库和 BrowserStack 账号的人都能运行它们。

## 各环节在哪里运行

| 环节 | 在哪里运行 |
| --- | --- |
| 录制场景 | 你的电脑：「移动测试」面板驱动本地桥接程序，本地桥接程序再驱动 BrowserStack 设备 |
| 编译片段、编写和导出测试、失败分类 | 助手，只处理文件 |
| 试运行、完整运行、重跑 | 团队的 Jenkins 流水线，用 behave 和 Appium 客户端运行这个 Python 项目 |

Portal 和助手都不会连接 BrowserStack。

## 开始之前

- **QA Assistant 类型的助手**：创建助手时选择 *QA Assistant* 类型。它带有这个流程用到的技能和指令，其他类型没有。
- **连接器 > BrowserStack**：填入你的用户名和访问密钥，并启用该连接器。聊天中的**移动测试**按钮只在这个连接器启用时出现，而且只有助手的所有者能看到。录制设备运行 Appium 2.19.0（可以在连接器的高级设置中改用其他版本）；BrowserStack 自己的默认版本 Appium 1.22.0 不认识 Inspector 的返回、主屏幕和应用切换按钮。
- **连接器 > 本地桥接程序**：在你的电脑上安装一次本地桥接程序（`efp-bridge`），录制都通过它进行。BrowserStack 页面上的*测试 BrowserStack* 会检查你的电脑能否连到 BrowserStack，以及电脑上是否有 BrowserStack Local。
- **连接器 > Jenkins** 和 **GitHub**：助手用你的 Jenkins 连接器启动移动场景流水线，并通过 GitHub 把测试提交到团队的测试仓库。Jenkins 管理员只需设置一次流水线，把测试账号写在一个 JSON 用户文件中，以 Secret file 类型的凭证保存在 Jenkins 里（每个账号一个 profile）。
- **Jira**：委派需要你的 Jira 连接器。请业务分析师在每个 Examples 行中填写预期结果；没有预期结果的行无法校验，助手会把它标出来，而不会自己编一个值。

## 录制场景

打开与助手的聊天，在工具栏中选择**移动测试**。面板分为三部分：顶部是设备，然后是显示下一步的进度条，最后是当前步骤本身。点齿轮图标可以打开设置（本地桥接程序、代理、上传安装包）。

1. 如果面板提示本地桥接程序没有运行，点**启动桥接程序**。这样启动桥接程序时不会打开 EFP 浏览器窗口；那个窗口属于聊天的浏览器自动化，聊天需要时才会打开。
2. 选择安装包、平台和设备，然后点**启动并打开 Inspector**。设备列表中手机在前、平板在后；选择**最新的手机（默认）**，就由桥接程序挑选该平台最新的手机。面板会按平台记住你上次的选择。桥接程序会启动设备并占用它；面板会显示它正在做什么，通常需要一分钟左右，如果你的并行会话都在忙，会更久。设备一就绪，Inspector 就会在单独的标签页中打开并连接到设备，无需输入任何内容。（如果你的 Portal 没有自带 Inspector，按钮会显示为**启动录制设备**，设备菜单中会显示桌面版 Appium Inspector 所需的连接详情。）重新加载页面会接上正在进行的启动；设备启动后，**取消**会释放设备。
3. 在 Inspector 中录制。它以 **Tap/Swipe By Coordinates** 模式打开，所以你可以像在手机上一样，在截图上点击和滑动；桥接程序会把每次点击匹配到点击位置下的元素。当屏幕显示应用正在加载（转圈图标、「loading」字样）时，页面会在后台观察设备，加载结束后自动刷新；否则请在设备就绪后点 **Refresh Source & Screenshot**，因为 Inspector 每次操作后只读取一次画面。要在输入框中输入内容，请切换到 **Select Elements**，选中该输入框，然后使用 **Send Keys**。所有经过 Inspector 的操作都会被桥接程序录制；Inspector 自带的录制器（它的 *Start Recording* 按钮和 *Recorder* 标签页，只会把命令转换成代码）已被隐藏。BrowserStack 自己网站上的实时设备画面，桥接程序是看不到的。设备菜单（设备卡片上的三个点）也可以在 Portal 内、面板旁边打开 Inspector。
4. 输入真实的值，包括密码。密码字段的内容永远不会被保存；助手会为每个密码起一个名称（例如 `MOBILE_SECRET_PASSWORD`），供流水线的凭证使用。其他值会成为测试数据的参数。
5. 把整个场景走完，然后点**保存录制**。录制会存入助手的工作区。助手会按录制经过的各个界面整理它，并在聊天中的审阅卡片上提出在哪里拆分成片段：批准拆分，或说明要修改什么。然后助手会编译每个片段，并告诉你它的稳健程度。片段生成后，进度条会前进到「回放」。（如果你在开始前列出了片段名称，就改为每录完一个片段保存一次；每个片段保存后会直接编译。）
6. 在根据片段生成任何脚本之前，先在**回放**下回放编译好的片段。勾选片段（你刚批准的拆分中的片段已经勾选），选择起点（「重启应用」、Android 上的「先清除应用数据」，或「设备当前显示的界面」），输入片段用到的密码，然后点**回放**。回放会从 Inspector 借用设备，结束后再交还；在此期间 Inspector 只能旁观。结果会存入助手的工作区并发到聊天中，聊天中的卡片会显示每个片段的结果及其后的截图，或者失败的步骤和停下时的界面。助手会审阅结果：修复失败的步骤，并请你再回放一次。每个片段都通过后才会生成脚本。密码只保留在页面和本地桥接程序中，助手永远看不到。
7. 要在同一台设备上录制另一个场景，继续录制并再次保存即可。设备菜单中的**结束录制**会释放设备。

设备每次占用 30 分钟；**再占用 30 分钟**可以延长占用时间。录制期间请保持桥接程序运行：如果会话五分钟内没有收到任何命令，BrowserStack 会结束它。

## 资料库

设备卡片下方的**资料库**标签页列出这个助手的工作区为移动测试保存的内容。查看它不需要设备。

- **片段**，按平台列出：步骤、评分和还有多少步需要检查（编译器写进文件的内容）、编译时间，以及是否有回放通过。**回放**会在「会话」下勾选该片段（如果已占用设备，会直接在那里开始）；**查看**按助手编写的样子显示片段的步骤；**删除**会把它从工作区移除并通知助手，助手会在所有用到它的场景中把它标记为需要重新录制。
- **录制**：每个录制的保存时间、大小，以及它的拆分是否已提出、是否已编译。**拆分**会请助手重新提出拆分方案；**删除**会移除该录制及其拆分文件（已经从它编译出的片段会保留）。
- **回放**：每次回放的结果以及它运行的片段。**详情**显示与聊天中相同的卡片，包括截图；**删除**会移除报告及其文件，不会通知助手。

删除前会先确认。助手会收到 `Segment <name> deleted: <path>` 或 `Recording <name> deleted: <path>`，并据此让场景计划保持同步。

## 录制评分的含义

| 评分 | 含义 |
| --- | --- |
| good | 每一步都通过 id 或文本定位元素 |
| fair | 有些步骤需要检查：按坐标点击，或按位置选取元素 |
| poor | 大多数步骤依赖屏幕位置；请应用开发人员添加 accessibility id 或 resource id，然后重新录制 |

## 查看结果

每次场景运行都有一张证据卡片：结果、设备、BrowserStack 会话、视频，以及各检查点的截图。流水线运行期间，该次运行的任务页面会显示场景矩阵；运行结束后会显示每个失败的分类结果，并附上缺陷或修复的链接。
