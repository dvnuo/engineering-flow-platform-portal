## 你发布的是什么

一个应用就是 GitHub 仓库里的一个目录，里面有一份清单 `efp-app.json`。Portal 用平台的只读服务账号读取这个目录，交给应用宿主；宿主安装它的依赖、启动它，并在它自己的地址下提供服务。应用可以是 Python Web 应用（`fastapi`、`flask`、`streamlit`、`gradio`，或者任何能提供 HTTP 服务的 `command`），也可以是 `static` 静态站点。

本页讲的是 Portal 这一侧：登记、部署和照看应用。Python SDK、各个框架的细节以及更完整的排错清单，见 `engineering-flow-platform-app` 仓库中的开发者指南 `docs/DEVELOPING_APPS.md`。同一个仓库里还有 SDK 参考手册（`docs/SDK_REFERENCE.md`）、把现有项目转换成应用的指南（`docs/CONVERTING_A_PROJECT.md`）、可以直接照抄的示例应用（`examples/`），以及 `AGENTS.md`：把同样的规则写成了交给 AI Agent 的任务说明。

## 从起步模板开始

```
pip install efp-app-sdk
efp-app init fastapi my-app
cd my-app
efp-app dev
```

`efp-app init` 会生成一个带清单、可以运行的应用；`efp-app dev` 按宿主的方式在你的电脑上运行它。把这个目录推送到平台能读取的仓库，就可以登记了。

## 清单

```json
{
  "name": "Mind map",
  "description": "Draw and share mind maps.",
  "icon": "icon.png",
  "type": "fastapi",
  "entry": "main:app",
  "requirements": "requirements.txt",
  "health_path": "/"
}
```

| 字段 | 含义 |
|---|---|
| `name` | 必填；应用的名称，登记时可以另起一个 |
| `description` | 显示在应用卡片上的一两句话 |
| `icon` | 目录中的一个 PNG、JPEG、GIF 或 WebP 文件 |
| `type` | `fastapi`、`flask`、`streamlit`、`gradio`、`command` 或 `static` |
| `entry` | FastAPI 和 Flask 写 `main:app`，Streamlit 和 Gradio 写脚本，静态站点写目录 |
| `requirements` | 依赖文件，不写就是 `requirements.txt` |
| `health_path` | 宿主用来确认应用有响应的路径，默认是 `/` |
| `owners` | 可选；可以发布这个目录的 Portal 用户名 |

不写 `owners`，任何成员都可以把这个目录登记成自己的应用。写上用户名（例如 `"owners": ["alice", "bob"]`），就只有这些成员可以登记和部署它。Portal 读取所有仓库用的是同一个服务账号，它能读到的仓库里可能有一些是部分成员在 GitHub 上打不开的，所以当这份代码不该让 Portal 上的每个人都能运行时，就写上 `owners`。

## 登记：四项内容

**应用 > 新建应用**只问四项：仓库、分支或标签、入口目录（放 `efp-app.json` 的那个文件夹；在仓库顶层就留空）和名称。前三项一填好，Portal 就会读取仓库并显示找到了什么：应用的类型、名称和它将得到的地址。有问题时，它会说明是什么问题、怎么解决：

- **Portal 无法读取这个仓库。** 它会写明服务账号；把这个账号以 Read 角色加入仓库即可。
- **efp-app.json 里没有你的用户名。** 清单用 `owners` 限定了谁可以发布，其中没有你。把你的用户名加进去，提交并推送。
- **efp-app.json 需要修改。** 逐条列出不符合的规则。

**创建并部署**会登记应用并开始第一次部署。地址由名称生成，之后不会再变，也不会再分配给别的应用。

## 部署与回退

一次部署会取分支或标签 上最新的提交，读取其中的清单，把代码发给宿主；宿主解包、安装依赖、启动应用、确认它有响应，然后才切换过去。应用页面会实时显示每一步和日志；依赖装不上时，日志里是 pip 自己的报错。部署失败不会影响原来正在运行的版本。

- **概览**会说明正在运行的版本落后分支多少个提交，并提供**部署最新版本**。
- **部署**可以部署另一个分支或标签（之后应用就跟随它），并保留历史记录。
- **回退**会回到当前版本之前运行的那个版本。

部署前先运行 `efp-app check`。应用是在 `/<name>/` 下提供服务的，所以页面、脚本或样式表里以 `/` 开头的 URL 会指到应用之外；这个检查能找出这类问题，而应用在你自己电脑上直接运行在根地址时，它们是看不出来的。想亲眼看到它们，可以按这里的方式运行应用：`efp-app dev --prefix <name>` 会把应用放在 `/<name>/` 下提供服务，并把每个跑到应用之外的请求打印出来。

## 令牌与本地开发

每个应用有一个令牌。部署后的应用会自动拿到它。要在自己的电脑上用真实的模型提供方和连接器运行应用，请把**设置 > 应用令牌**里的令牌复制到 `.env`：

```
EFP_APP_TOKEN=efpa_...
EFP_PORTAL_URL=https://<this Portal's address>
```

然后用 `efp-app dev` 启动。本地发出的调用是真实的：会用到你的模型提供方和图片分析连接器，计入应用的每日上限，也会访问你连接器背后的真实系统。

不要把 `.env` 提交到仓库。只要能访问 Portal，令牌在任何地方都能用；页面上会显示它最近一次使用的时间，以及来自集群内还是集群外。如果令牌泄露，请**重置令牌**：旧令牌立即失效，应用会带着新令牌重启。

## 谁可以打开

| 范围 | 谁可以进入 |
|---|---|
| 仅所有者 | 只有你；这是默认值 |
| 所有者所在的组 | 你所在组的每位成员 |
| 所有成员 | 所有能登录 Portal 的人 |
| 任何人 | 完全不需要登录 |

只有管理员开启了这一项时才会提供**任何人**，而且要等管理员批准这个应用后才生效；在那之前，所有成员都可以打开它。

## 应用可以使用你的什么

应用的代码可以通过 SDK 调用你的模型提供方和连接器，也可以通过你的图片分析连接器读取图片。这些默认都是关闭的，要在**设置**里打开，而且每一项打开前都会先问你：

- **模型提供方。** *访问者使用这个应用会消耗你的 Copilot，也可能让你自己的聊天变慢。*不管访问者是谁，每次调用都走你自己的模型提供方，并受每日积分和 token 上限的限制。达到上限后，调用会被拒绝，直到第二天（UTC）。
- **连接器**（Jira、Confluence、GitHub、Jenkins、Nexus、Splunk）。*访问者会以你连接器的账号读取这些系统中的内容。*除非你另外允许写入，连接器是只读的。
- **图片分析。** *访问者交给这个应用的图片会以你的图片分析连接器的账号读取，每次调用都计入应用的每日上限。*应用就一到四张图片（JPEG、PNG、WebP 或 GIF，每张最多 5 MiB）提出一个问题，由你的[图片分析连接器](#/help/connect-image_analysis)的模型回答。它是一个独立的开关：不需要为应用开启模型提供方，一次图片调用按一次模型调用计入同一个每日上限。这个连接器还没有设置好时，应用会被告知这一点，图片不会被读取。它没有可以写入的东西，所以没有**可写入**选项。
- 在任一项开启的情况下**扩大范围**时会再提醒你一次，因为会有更多人以你的名义消耗额度、读取内容。

## 日常照看

- **环境变量**：代码从环境中读取的设置和密钥。名称不能以 `EFP_` 开头，也不能是系统加载程序时读取的名称（`LD_...`、`GCONV_PATH`、`GLIBC_TUNABLES`）；值默认隐藏，点了才显示；保存后应用会重启。
- **日志**：应用输出的内容，实时跟随。可以暂停阅读，也可以下载保存。
- **用量**：请求数、访问者、错误和响应时间；模型调用（包括图片调用）以及相对每日上限的积分消耗；连接器调用；访问最多的人；内存和数据大小。
- **数据**：应用在宿主上保存了多少内容。重启和部署都不会丢。**清空数据**会永久删除。
- **操作记录**：谁部署、修改、重置或下架了什么，以及宿主上报了什么。

## 模板

在**设置 > 模板**里把应用提供为模板，然后把仓库的某个标签发布为一个版本。其他成员可以从某个版本创建自己的应用：他们得到的是那个版本的代码，永远拿不到你的令牌、变量和数据。他们的应用会停留在所选的版本上；你发布新版本后，他们会看到升级提示，由他们自己决定什么时候升级。

想修改别人写的应用的代码，请用自己的账号在 GitHub 上 fork 它的仓库（链接在**设置 > 代码**里），再把你的 fork 登记为一个新应用。

## 限制

- 只有一个 Python 版本，由平台决定。依赖以 wheel 的形式从平台的包仓库安装；不能安装系统软件包。
- 每个应用一个进程，并有内存上限。超过上限的应用会被停止，并显示原因。
- 一段时间没有访问者，应用就会被停止，下一次访问时再启动。请在请求处理函数里完成工作，把状态存进存储：不要有后台任务和定时器，重要的东西不要只放在内存里。
- 代码目录是只读的。需要保留下来的内容要通过 SDK 的存储保存，存储有配额。
- 所有应用共用一个地址，因此浏览器的本地存储在它们之间是共享的：不要在那里放机密内容。摄像头、麦克风、定位和屏幕捕获都是关闭的。

## 出问题时

- **安装依赖**失败：某个包没有适合宿主 Python 版本的 wheel，或者不在平台的包仓库里。换一个有 wheel 的版本。
- **检查应用是否响应**失败：应用必须监听 `127.0.0.1` 和 `PORT` 中的端口，并及时响应它的 `health_path`。
- **本地正常，部署后没有样式或出现 404**：有 URL 以 `/` 开头。运行 `efp-app check`。
- **已崩溃**或**被宿主停止**：查看**日志**；如果是内存问题，查看**用量**。

访问者一侧的说明见[使用应用](#/help/using-apps)。
