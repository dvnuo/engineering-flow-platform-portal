## 用途

查看 AWS 账号和 EKS 集群：实例、AMI、CloudWatch 日志，以及集群中正在运行的内容。

以读取为主：助手只报告它发现的情况，而不会更改基础设施。它通过 `aws-auth` CLI 登录，每个账号行对应一个 AWS CLI profile，并以只读方式使用 kubectl（get、describe、logs、events）。

## 每个账号一行

每一行是助手可以登录的一个 AWS 账号：

- **名称**会成为助手通过 `--profile` 传入的 AWS CLI profile，所以要简短且唯一，例如 `cps-dev`。
- **账号 ID** 是 12 位的 AWS 账号编号。
- **角色**是要在该账号中承担的 IAM 角色。请选择只读角色；助手只能做该角色允许的事。
- **区域**是这个账号使用的区域，从 `ap-east-1`、`eu-west-1` 和 `us-east-1` 中选择；选中的第一个区域是集群命令的默认区域。

关闭某一行的开关，可以保留这一行，但不再提供给助手。请求没有指明账号时，使用默认账号。

## PrivateLink 后面的集群

如果 EKS 集群的 API 服务器端点是私有的，就无法通过 AWS 为它上报的地址访问；从其他 VPC 访问时，要经过 PrivateLink 接口端点。请在这里列出每个这样的集群，每个集群一行，助手的 `kubectl` 上下文会自动指向该地址：

- **账号**从上方的账号行中选择。
- **集群**是 EKS 集群名称。
- **区域**是可选项，同样从这三个区域中选择，用于同一账号的多个区域中存在同名集群的情况。
- **私有端点**是 PrivateLink 地址，例如 `https://vpce-0ab12cd.vpce-svc-0123.eu-west-1.vpce.amazonaws.com`。
- **证书颁发机构**说明在该地址应答的是谁的证书。*集群 CA* 适用于把 TLS 直接透传到 API 服务器的端点：证书是集群自己的，助手会保留集群 CA，并按集群的主机名验证证书。*系统信任库*适用于用自己的证书终止 TLS 的端点，该证书由运行时已经信任的 CA 针对端点名称签发：这时助手会去掉内嵌的集群 CA，像普通 HTTPS 客户端一样验证。无论哪种情况，验证都不会关闭。
- **TLS 服务器名称**可以留空：证书会按集群的主机名（集群 CA）或端点的主机名（系统信任库）验证。只有平台团队告诉你证书使用了其他名称时，才需要设置。

添加一行之前，助手（或你自己在运行时中）可以用 `aws-auth eks endpoint --account <name> --cluster <cluster>
--private-endpoint <address> --json` 检查这个地址。它会报告该地址是否有响应、它出示的证书是集群自己的还是运行时信任的证书，以及因此应选择哪种证书颁发机构设置。如果证书不被任何一方信任，说明运行时镜像中缺少平台的 CA；检查会直接指出这一点，而不是去猜测。

## 提供方

- **adfs-assume**（默认）用上方的域、用户名和密码登录 ADFS，并在每个账号中承担列出的角色。
- **saml2aws** 通过 ADFS IdP URL 使用同一个目录账号。
- **assume-role** 不需要密码：它以运行时中已有的来源 profile 的凭证，承担每个角色。

## 出错时

token 过期或缺失时，会表现为 aws 或 kubectl 报错，助手会用 `aws-auth login` 重新登录。只有能承担其角色的行才可用，所以请先检查账号 ID 和角色名称。
