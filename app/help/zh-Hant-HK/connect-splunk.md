## 用途

在助手排解問題時搜尋你的日誌：某個服務最近一小時的錯誤、某個請求 ID 在各個組件中的記錄、某件事發生的頻率。它透過 `splunk` CLI 執行搜尋，而且一律附帶時間範圍和結果數量上限，所以即使查詢寫得不夠嚴謹，也不會拉取整個索引。

它只讀取搜尋結果；不會建立警報、已儲存搜尋或儀表板，也從不寫入索引。

## 填寫什麼

- **URL** 是管理 API 的地址，不是網頁地址：連接埠通常是 `8089`，例如 `https://splunk-api.example.com:8089`。
- **驗證權杖**在 Splunk 的 Settings → Tokens 中建立。如果你的 Splunk 不簽發權杖，可改用用戶名稱和密碼。
- **預設索引**是查詢未指定索引時搜尋的索引，例如 `app_prod`。**預設起始時間**是請求未提供時間範圍時採用的範圍，使用 Splunk 的相對時間寫法，例如 `-1h` 或 `-24h`。**最大結果數**限制一次搜尋最多傳回多少個事件（1 至 10000）。
- **名稱**是助手用 `--instance` 指定這個實例時所用的名字。
- **應用程式**是你希望助手看到的已儲存搜尋、巨集和查找表（lookup）所屬的 Splunk 應用程式。只有當這些物件是全域物件時才留空。它就是你在 Splunk 中瀏覽這些物件時 URL 裏的名稱，例如 `/en-US/app/search/` 中的 `search`。不填的話，助手只會在全域命名空間中尋找，然後報告什麼也找不到。**擁有者**與應用程式配合使用，通常留空，表示該角色看得到的任何擁有者。

## 無法正常運作時

管理連接埠出現證書錯誤十分常見：這個連接埠經常使用自簽署證書。請向 Splunk 管理員查詢哪個地址出示的是受信任的證書。搜尋沒有傳回任何結果，通常是時間範圍太窄或索引不對；助手會連同結果一併報告這兩項。
