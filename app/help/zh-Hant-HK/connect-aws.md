## 用途

查看 AWS 帳戶和 EKS 叢集：實例、AMI、CloudWatch 日誌，以及叢集中正在執行的內容。

以讀取為主：助手只會報告它發現的情況，而不會更改基礎設施。它透過 `aws-auth` CLI 登入，每個帳戶行對應一個 AWS CLI profile，並以唯讀方式使用 kubectl（get、describe、logs、events）。

## 每個帳戶一行

每一行是助手可以登入的一個 AWS 帳戶：

- **名稱**會成為助手透過 `--profile` 傳入的 AWS CLI profile，所以要簡短而且不能重複，例如 `cps-dev`。
- **帳戶 ID** 是 12 位數字的 AWS 帳戶號碼。
- **角色**是要在該帳戶中承擔的 IAM 角色。請選擇唯讀角色；助手只能做該角色允許的事。
- **區域**是這個帳戶使用的區域，從 `ap-east-1`、`eu-west-1` 和 `us-east-1` 中選擇；選取的第一個區域是叢集指令的預設區域。

關閉某一行的開關，即可保留該行，但不再提供給助手使用。請求沒有指明帳戶時，會使用預設帳戶。

## PrivateLink 後面的叢集

如果 EKS 叢集的 API 伺服器端點是私有的，就無法透過 AWS 為它回報的地址存取；從其他 VPC 存取時，要經由 PrivateLink 介面端點。請在這裏列出每個這樣的叢集，每個叢集一行，助手的 `kubectl` 上下文會自動指向該地址：

- **帳戶**從上方的帳戶行中選擇。
- **叢集**是 EKS 叢集名稱。
- **區域**是可選項，同樣從這三個區域中選擇，用於同一帳戶的多個區域都有同名叢集的情況。
- **私有端點**是 PrivateLink 地址，例如 `https://vpce-0ab12cd.vpce-svc-0123.eu-west-1.vpce.amazonaws.com`。
- **憑證機構**說明在該地址回應的是誰的證書。*叢集 CA* 適用於把 TLS 直接透傳到 API 伺服器的端點：證書是叢集自己的，助手會保留叢集 CA，並按叢集的主機名稱驗證證書。*系統信任庫*適用於以自己的證書終止 TLS 的端點，該證書由執行環境已經信任的 CA 按端點名稱簽發：這時助手會移除內嵌的叢集 CA，像一般 HTTPS 用戶端一樣進行驗證。無論哪種情況，驗證都不會關閉。
- **TLS 伺服器名稱**可以留空：證書會按叢集的主機名稱（叢集 CA）或端點的主機名稱（系統信任庫）驗證。只有平台團隊告訴你證書使用了其他名稱時，才需要設定。

新增一行之前，助手（或你自己在執行環境中）可以用 `aws-auth eks endpoint --account <name> --cluster <cluster>
--private-endpoint <address> --json` 檢查這個地址。它會報告該地址是否有回應、它出示的證書是叢集自己的還是執行環境信任的證書，以及因此應選擇哪一種憑證機構設定。如果證書不受任何一方信任，代表執行環境映像檔中缺少平台的 CA；檢查會直接指出這一點，而不會胡亂猜測。

## 提供者

- **adfs-assume**（預設）使用上方的網域、用戶名稱和密碼登入 ADFS，並在每個帳戶中承擔列出的角色。
- **saml2aws** 透過 ADFS IdP URL 使用同一個目錄帳戶。
- **assume-role** 不需要密碼：它以執行環境中已有的來源 profile 的憑證，承擔每個角色。

## 出錯時

token 過期或缺失時，會顯示為 aws 或 kubectl 錯誤，助手會用 `aws-auth login` 重新登入。只有能承擔其角色的行才可用，所以請先檢查帳戶 ID 和角色名稱。
