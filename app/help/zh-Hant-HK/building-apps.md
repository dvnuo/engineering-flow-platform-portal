## 你發佈的是甚麼

一個應用程式就是 GitHub 儲存庫中的一個目錄，裏面有一份資訊清單 `efp-app.json`。Portal 以平台的唯讀服務帳戶讀取這個目錄，交給應用程式宿主；宿主安裝它的依賴項目、啟動它，並在它自己的地址下提供服務。應用程式可以是 Python 網頁應用程式（`fastapi`、`flask`、`streamlit`、`gradio`，或者任何能提供 HTTP 服務的 `command`），也可以是 `static` 靜態網站。

本頁說明的是 Portal 這一邊：登記、部署和照顧應用程式。Python SDK、各個框架的細節以及更完整的疑難排解清單，請參閱 `engineering-flow-platform-app` 儲存庫中的開發者指南 `docs/DEVELOPING_APPS.md`。

## 從入門範本開始

```
pip install efp-app-sdk
efp-app init fastapi my-app
cd my-app
efp-app dev
```

`efp-app init` 會產生一個附有資訊清單、可以執行的應用程式；`efp-app dev` 按宿主的方式在你的電腦上執行它。把這個目錄推送到平台能讀取的儲存庫，就可以登記了。

## 資訊清單

```json
{
  "name": "Mind map",
  "description": "Draw and share mind maps.",
  "icon": "icon.png",
  "type": "fastapi",
  "entry": "main:app",
  "requirements": "requirements.txt",
  "health_path": "/"
}
```

| 欄位 | 意思 |
|---|---|
| `name` | 必填；應用程式的名稱，登記時可以另取一個 |
| `description` | 顯示在應用程式卡片上的一兩句話 |
| `icon` | 目錄中的一個 PNG、JPEG、GIF 或 WebP 檔案 |
| `type` | `fastapi`、`flask`、`streamlit`、`gradio`、`command` 或 `static` |
| `entry` | FastAPI 和 Flask 填 `main:app`，Streamlit 和 Gradio 填腳本，靜態網站填目錄 |
| `requirements` | 依賴項目檔案，不填就是 `requirements.txt` |
| `health_path` | 宿主用來確認應用程式有回應的路徑，預設是 `/` |
| `owners` | 可選；可以發佈這個目錄的 Portal 用戶名稱 |

不寫 `owners`，任何成員都可以把這個目錄登記成自己的應用程式。寫上用戶名稱（例如 `"owners": ["alice", "bob"]`），就只有這些成員可以登記和部署它。Portal 讀取所有儲存庫用的是同一個服務帳戶，它能讀取的儲存庫中可能有一些是部分成員在 GitHub 上無法開啟的，所以當這份程式碼不應讓 Portal 上的每個人都能執行時，就寫上 `owners`。

## 登記：四項內容

**應用程式 > 新增應用程式**只問四項：儲存庫、分支或標籤、入口目錄（放置 `efp-app.json` 的那個資料夾；在儲存庫頂層就留空）和名稱。前三項一填好，Portal 就會讀取儲存庫並顯示找到了甚麼：應用程式的類型、名稱和它將得到的地址。有問題時，它會說明是甚麼問題、怎樣解決：

- **Portal 無法讀取這個儲存庫。** 它會寫明服務帳戶；把這個帳戶以 Read 角色加入儲存庫即可。
- **efp-app.json 中沒有你的用戶名稱。** 資訊清單用 `owners` 限定了誰可以發佈，其中沒有你。把你的用戶名稱加進去，提交並推送。
- **efp-app.json 需要修改。** 逐條列出不符合的規則。

**建立並部署**會登記應用程式並開始第一次部署。地址由名稱產生，之後不會再變，也不會再分配給其他應用程式。

## 部署與還原

一次部署會取分支或標籤 上最新的提交，讀取其中的資訊清單，把程式碼傳給宿主；宿主解壓、安裝依賴項目、啟動應用程式、確認它有回應，然後才切換過去。應用程式頁面會即時顯示每一步和日誌；依賴項目安裝不了時，日誌中是 pip 自己的錯誤訊息。部署失敗不會影響原本正在執行的版本。

- **概覽**會說明正在執行的版本落後分支多少個提交，並提供**部署最新版本**。
- **部署**可以部署另一個分支或標籤（之後應用程式就跟隨它），並保留歷史記錄。
- **還原**會返回目前版本之前執行的那個版本。

部署前先執行 `efp-app check`。應用程式是在 `/<name>/` 下提供服務的，所以頁面、腳本或樣式表中以 `/` 開頭的 URL 會指向應用程式之外；這項檢查能找出這類問題，而它們在你自己的電腦上是看不出來的。

## 權杖與本機開發

每個應用程式有一個權杖。部署後的應用程式會自動取得它。要在自己的電腦上以真實的模型提供者和連接器執行應用程式，請把**設定 > 應用程式權杖**中的權杖複製到 `.env`：

```
EFP_APP_TOKEN=efpa_...
EFP_PORTAL_URL=https://<this Portal's address>
```

然後以 `efp-app dev` 啟動。本機發出的呼叫是真實的：會用到你的模型提供者，計入應用程式的每日上限，也會存取你連接器背後的真實系統。

不要把 `.env` 提交到儲存庫。只要能連上 Portal，權杖在任何地方都能使用；頁面上會顯示它最近一次使用的時間，以及來自叢集內還是叢集外。如果權杖外洩，請**重設權杖**：舊權杖即時失效，應用程式會帶着新權杖重新啟動。

## 誰可以開啟

| 範圍 | 誰可以進入 |
|---|---|
| 只限擁有者 | 只有你；這是預設值 |
| 擁有者所屬的組 | 你所屬組的每位成員 |
| 所有成員 | 所有能登入 Portal 的人 |
| 任何人 | 完全不需要登入 |

只有管理員開啟了這一項時才會提供**任何人**，而且要待管理員批准這個應用程式後才生效；在此之前，所有成員都可以開啟它。

## 應用程式可以使用你的甚麼

應用程式的程式碼可以透過 SDK 呼叫你的模型提供者和連接器。兩者預設都是關閉的，要在**設定**中開啟，而且每一項開啟前都會先問你：

- **模型提供者。** *訪客使用這個應用程式會消耗你的 Copilot，亦可能令你自己的聊天變慢。*不論訪客是誰，每次呼叫都使用你自己的模型提供者，並受每日點數和 token 上限的限制。達到上限後，呼叫會被拒絕，直至翌日（UTC）。
- **連接器**（Jira、Confluence、GitHub、Jenkins、Nexus、Splunk）。*訪客會以你連接器的帳戶讀取這些系統的內容。*除非你另外容許寫入，連接器是唯讀的。
- 在任何一項開啟的情況下**擴大範圍**時會再提醒你一次，因為會有更多人以你的名義消耗額度、讀取內容。

## 日常照顧

- **環境變數**：程式碼從環境中讀取的設定和密鑰。名稱不能以 `EFP_` 開頭；值預設隱藏，按一下才顯示；儲存後應用程式會重新啟動。
- **日誌**：應用程式輸出的內容，即時跟隨。可以暫停閱讀，也可以下載保存。
- **用量**：請求數、訪客、錯誤和回應時間；模型呼叫以及相對每日上限的點數消耗；連接器呼叫；到訪最多的人；記憶體和數據大小。
- **數據**：應用程式在宿主上儲存了多少內容。重新啟動和部署都不會遺失。**清除數據**會永久刪除。
- **操作記錄**：誰部署、修改、重設或下架了甚麼，以及宿主回報了甚麼。

## 範本

在**設定 > 範本**中把應用程式提供為範本，然後把儲存庫的某個標籤發佈為一個版本。其他成員可以從某個版本建立自己的應用程式：他們得到的是該版本的程式碼，永遠取不到你的權杖、變數和數據。他們的應用程式會停留在所選的版本上；你發佈新版本後，他們會看到升級提示，由他們自行決定何時升級。

想修改其他人編寫的應用程式的程式碼，請以自己的帳戶在 GitHub 上 fork 它的儲存庫（連結在**設定 > 程式碼**中），再把你的 fork 登記為一個新應用程式。

## 限制

- 只有一個 Python 版本，由平台決定。依賴項目以 wheel 的形式從平台的套件庫安裝；不能安裝系統套件。
- 每個應用程式一個程序，並有記憶體上限。超過上限的應用程式會被停止，並顯示原因。
- 一段時間沒有訪客，應用程式就會被停止，下一次到訪時再啟動。請在請求處理函式中完成工作，把狀態存入儲存空間：不要有背景工作和排程器，重要的東西不要只放在記憶體中。
- 程式碼目錄是唯讀的。需要保留下來的內容要透過 SDK 的儲存空間保存，儲存空間設有配額。
- 所有應用程式共用一個地址，因此瀏覽器的本機儲存空間在它們之間是共用的：不要在那裏放機密內容。相機、麥克風、位置和螢幕擷取都是關閉的。

## 出問題時

- **安裝依賴項目**失敗：某個套件沒有適合宿主 Python 版本的 wheel，或者不在平台的套件庫中。換一個有 wheel 的版本。
- **檢查應用程式有否回應**失敗：應用程式必須監聽 `127.0.0.1` 和 `PORT` 中的連接埠，並及時回應它的 `health_path`。
- **本機正常，部署後沒有樣式或出現 404**：有 URL 以 `/` 開頭。執行 `efp-app check`。
- **已崩潰**或**被宿主停止**：查看**日誌**；如果是記憶體問題，查看**用量**。

訪客一方的說明請參閱[使用應用程式](#/help/using-apps)。
