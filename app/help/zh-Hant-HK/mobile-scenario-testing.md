## 整體流程

1. 業務分析員（BA）在 Jira 中完成一項需求，並把它移到團隊約定的狀態，例如 **Ready for Test**。
2. 由這次狀態變更觸發的委派會讓助手草擬情境：分組的 Scenario Outline 及其 Examples 表，涵蓋正面和負面用例，每個 Examples 行都附有預期結果。
3. 你在任務頁面上批准這些情境（一張審閱卡片：剔選要保留的情境，說明要修改什麼）。
4. 你在自己的電腦上，用一部 BrowserStack 真機一次錄完一個情境，每個平台錄一次。助手會建議如何把錄製拆分成可重用的片段（登入、跳過介紹頁、選擇貨幣），由你確認拆分方式。然後你在同一部裝置上重播這些片段，親眼確認它們能正常運作，之後才會產生腳本。
5. 助手把已批准的情境和你的片段轉換成一個普通的 Python 測試專案（你批准的 Gherkin、對應的步驟定義，以及寫成函數的片段，其中每一行錄製的程式碼都標有 `# recorded:`），提交到團隊的測試儲存庫，並讓 Jenkins 流水線在一部裝置上為每個情境執行一行 Examples。然後由你批准。
6. 完整執行經由同一條流水線並行進行，並在構建頁面上發布 Cucumber 報告。每個情境最後都有結果、截圖和該次工作階段的影片；失敗會被歸入腳本偏移、產品缺陷、基礎設施或測試數據。這些測試不依賴 EFP：任何擁有該儲存庫和 BrowserStack 帳戶的人都可以執行。

## 各環節在哪裏執行

| 環節 | 在哪裏執行 |
| --- | --- |
| 錄製情境 | 你的電腦：「流動測試」面板驅動本機橋接程式，再由本機橋接程式驅動 BrowserStack 裝置 |
| 編譯片段、編寫和匯出測試、失敗分流 | 助手，只處理檔案 |
| 試執行、完整執行、重跑 | 團隊的 Jenkins 流水線，用 behave 和 Appium 用戶端執行這個 Python 專案 |

Portal 和助手都不會連接 BrowserStack。

## 開始之前

- **QA Assistant 類型的助手**：建立助手時選擇 *QA Assistant* 類型。它附帶這個流程用到的技能和指示，其他類型沒有。
- **連接器 > BrowserStack**：填入你的用戶名稱和存取密鑰，並啟用該連接器。聊天中的**流動測試**按鈕只在這個連接器啟用時出現，而且只有助手的擁有者看得到。錄製裝置執行 Appium 2.19.0（可在連接器的進階設定中改用其他版本）；BrowserStack 自己的預設版本 Appium 1.22.0 不認識 Inspector 的返回、主畫面和應用程式切換按鈕。
- **連接器 > 本機橋接程式**：在你的電腦上安裝一次本機橋接程式（`efp-bridge`），錄製都經由它進行。BrowserStack 頁面上的*測試 BrowserStack* 會檢查你的電腦能否連到 BrowserStack，以及電腦上有沒有 BrowserStack Local。
- **連接器 > Jenkins** 和 **GitHub**：助手用你的 Jenkins 連接器啟動流動情境流水線，並經由 GitHub 把測試提交到團隊的測試儲存庫。Jenkins 管理員只需設定一次流水線，把測試帳戶寫在一個 JSON 用戶檔案中，以 Secret file 類型的憑證保存在 Jenkins 裏（每個帳戶一個 profile）。
- **Jira**：委派需要你的 Jira 連接器。請業務分析員在每個 Examples 行中填寫預期結果；沒有預期結果的行無法核對，助手會把它標示出來，而不會自行編造一個值。

## 錄製情境

開啟與助手的聊天，在工具列中選擇**流動測試**。面板分為三部分：頂部是裝置，然後是顯示下一步的進度條，最後是當前步驟本身。按齒輪圖示可開啟設定（本機橋接程式、代理、上載安裝檔）。

1. 如果面板顯示本機橋接程式沒有執行，按**啟動橋接程式**。這樣啟動橋接程式時不會開啟 EFP 瀏覽器視窗；該視窗屬於聊天的瀏覽器自動化，聊天需要時才會開啟。
2. 選擇安裝檔、平台和裝置，然後按**啟動並開啟 Inspector**。裝置列表中手機在前、平板在後；選擇**最新的手機（預設）**，就由橋接程式挑選該平台最新的手機。面板會按平台記住你上次的選擇。橋接程式會啟動裝置並佔用它；面板會顯示它正在做什麼，通常約需一分鐘，如果你的並行工作階段都在忙，會更久。裝置一就緒，Inspector 就會在獨立的分頁中開啟並連接到裝置，無需輸入任何內容。（如果你的 Portal 沒有內置 Inspector，按鈕會顯示為**啟動錄製裝置**，裝置選單中會顯示桌面版 Appium Inspector 所需的連線詳情。）重新載入頁面會接回正在進行的啟動；裝置啟動後，**取消**會釋放裝置。
3. 在 Inspector 中錄製。它以 **Tap/Swipe By Coordinates** 模式開啟，所以你可以像在手機上一樣，在截圖上點按和滑動；橋接程式會把每次點按對應到點按位置下的元素。當螢幕顯示應用程式正在載入（轉圈圖示、「loading」字樣）時，頁面會在背景觀察裝置，載入完成後自動重新整理；否則請在裝置就緒後按 **Refresh Source & Screenshot**，因為 Inspector 每次操作後只會讀取一次畫面。要在輸入欄中輸入內容，請切換到 **Select Elements**，選取該輸入欄，然後使用 **Send Keys**。所有經過 Inspector 的操作都會被橋接程式錄製；Inspector 自帶的錄製器（它的 *Start Recording* 按鈕和 *Recorder* 分頁，只會把指令轉換成程式碼）已被隱藏。BrowserStack 自家網站上的即時裝置畫面，橋接程式是看不到的。裝置選單（裝置卡片上的三點圖示）也可以在 Portal 內、面板旁邊開啟 Inspector。
4. 輸入真實的值，包括密碼。密碼欄位的內容永遠不會被儲存；助手會為每個密碼命名（例如 `MOBILE_SECRET_PASSWORD`），供流水線的憑證使用。其他值會成為測試數據的參數。
5. 把整個情境走完，然後按**儲存錄製**。錄製會存入助手的工作區。助手會按錄製經過的各個畫面整理它，並在聊天中的審閱卡片上建議在哪裏拆分成片段：批准拆分，或說明要修改什麼。然後助手會編譯每個片段，並告訴你它的穩健程度。片段產生後，進度條會前進到「重播」。（如果你在開始前列出了片段名稱，就改為每錄完一個片段儲存一次；每個片段儲存後會直接編譯。）
6. 在根據片段產生任何腳本之前，先在**重播**下重播已編譯的片段。剔選片段（你剛批准的拆分中的片段已預先剔選），選擇起點（「重新啟動應用程式」、Android 上的「先清除應用程式數據」，或「裝置目前顯示的畫面」），輸入片段用到的密碼，然後按**重播**。重播會向 Inspector 借用裝置，結束後交還；在此期間 Inspector 只能觀看。結果會存入助手的工作區並傳到聊天中，聊天中的卡片會顯示每個片段的結果及其後的截圖，或失敗的步驟和停下時的畫面。助手會審閱結果：修正失敗的步驟，並請你再重播一次。每個片段都通過後才會產生腳本。密碼只留在頁面和本機橋接程式中，助手永遠看不到。
7. 要在同一部裝置上錄製另一個情境，繼續錄製並再次儲存即可。裝置選單中的**結束錄製**會釋放裝置。

裝置每次佔用 30 分鐘；**再佔用 30 分鐘**可以延長佔用時間。錄製期間請保持橋接程式執行：如果工作階段五分鐘內沒有收到任何指令，BrowserStack 會結束它。

## 資料庫

裝置卡片下方的**資料庫**分頁列出這個助手的工作區為流動測試保存的內容。查看它不需要裝置。

- **片段**，按平台列出：步驟、評分和還有多少步需要檢查（編譯器寫入檔案的內容）、編譯時間，以及是否有重播通過。**重播**會在「工作階段」下剔選該片段（如果已佔用裝置，會直接在那裏開始）；**檢視**按助手編寫的樣子顯示片段的步驟；**刪除**會把它從工作區移除並通知助手，助手會在所有用到它的情境中把它標記為需要重新錄製。
- **錄製**：每個錄製的儲存時間、大小，以及它的拆分是否已提出、是否已編譯。**拆分**會請助手重新提出拆分方案；**刪除**會移除該錄製及其拆分檔案（已經從它編譯出的片段會保留）。
- **重播**：每次重播的結果以及它執行的片段。**詳情**顯示與聊天中相同的卡片，包括截圖；**刪除**會移除報告及其檔案，不會通知助手。

刪除前會先確認。助手會收到 `Segment <name> deleted: <path>` 或 `Recording <name> deleted: <path>`，並據此讓情境計劃保持同步。

## 錄製評分的含義

| 評分 | 含義 |
| --- | --- |
| good | 每一步都透過 id 或文字定位元素 |
| fair | 部分步驟需要檢查：按座標點按，或按位置選取元素 |
| poor | 大部分步驟依賴螢幕位置；請應用程式開發人員加上 accessibility id 或 resource id，然後重新錄製 |

## 查看結果

每次情境執行都有一張證據卡片：結果、裝置、BrowserStack 工作階段、影片，以及各檢查點的截圖。流水線執行期間，該次執行的任務頁面會顯示情境矩陣；執行結束後會顯示每個失敗的分流結果，並附上缺陷或修正的連結。
