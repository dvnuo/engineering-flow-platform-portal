Recording on your computer

Portal and the assistants do not connect to BrowserStack. Recording runs on this computer through the local bridge, the program of Connectors > Local bridge: it starts a BrowserStack device with the settings above, holds it while you record, and passes Appium Inspector's commands to it. Open a chat with your assistant and choose Recording in the tool bar.

Looking for the local bridge…

Empty uses this computer's own proxy settings, including a PAC script, the way the browser does. Set one when the test or a recording is answered by a web filter's block page although the browser reaches BrowserStack. Kept in this browser only. A proxy that asks for a login takes it in the address, http://user:password@proxy.example.com:8080 (a domain user as DOMAIN%5Cuser); it goes only to the local bridge on this computer.

  • Install the local bridge once from Connectors > Local bridge; its package includes mobile-auto for recordings.
    • {% if appium_inspector_available %}
  • Portal hosts Appium Inspector: the Recording panel opens it already attached to the device. Nothing else to install.
    • {% else %}
  • Install Appium Inspector 2026.5.1 or later; the Recording panel shows how to attach it to the device.
    • {% endif %}
  • Upload the build to record in the Recording panel, or pick one your pipeline already uploaded.
  • Type real values while recording. Password fields are never stored; they become names such as MOBILE_SECRET_PASSWORD.
Test runs in Jenkins

Dry runs, full runs, and reruns go through your team's mobile scenario pipeline in Jenkins, which has its own BrowserStack account and keeps the test accounts' passwords as Jenkins credentials under the names the recordings use. The assistant starts the pipeline and brings back each scenario's result, screenshots, and video.
