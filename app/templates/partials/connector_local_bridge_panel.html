One program on your PC, efp-bridge, does both. Everything runs on your PC; the Portal only relays requests while a chat is open in this tab.

Step 1 · Download the bridge

Download the EFP local bridge{% if cli_version %} (version {{ cli_version }}){% endif %} for your system and unzip it into the bin folder of your home directory: %USERPROFILE%\bin (Windows) or ~/bin (macOS, Linux). Create the folder if it is missing and overwrite any files already there. No administrator rights are needed. The package holds the efp-bridge program, mobile-auto for mobile recordings, the installer for that system, and a README.

Step 2 · Install and start the bridge
  1. In the unzipped folder, double-click install-bridge.cmd (Windows) and enter {{ portal_origin }} when it asks for the Portal address, or run ./install-bridge.sh {{ portal_origin }} (macOS, Linux). It registers the efp-bridge:// link for your account only (no admin, no autostart). Equivalent command: efp-bridge register --origin {{ portal_origin }}
  2. Click Start bridge below. Chrome asks whether to open the EFP bridge: allow it (tick "always allow" to skip the prompt next time).
  3. A new Chrome window titled EFP opens with {{ start_url or portal_origin }} as its only tab. Sign in to your work sites there once; the window keeps its own logins.
  4. Closed that window? The bridge keeps running in the background: click Start bridge again to reopen it, or just send a message; the next browser action reopens it.
Start bridge
Browser automation

Assistants read and operate pages in the EFP Chrome window, a separate window with its own profile, so you sign in there once. The test asks the bridge for its version and lists the tabs open in that window. Nothing is changed on any page.

Mobile recording

The Recording panel in an assistant's chat starts a BrowserStack device from this computer and records what you do in Appium Inspector. The bridge runs mobile-auto from its own folder with your BrowserStack settings; there is nothing more to install.

Start the bridge (step 2) to check.

  • Bridge not detected: it is not running. Repeat step 2; if the efp-bridge link does nothing, run install-bridge.cmd (Windows) or install-bridge.sh (macOS, Linux) again.
  • Start bridge seems to do nothing: the launcher deliberately runs without a window. Every attempt is written to .efp/bridge/logs/bridge.log in your home folder; read the last lines there.
  • The EFP browser window is closed but the bridge shows as running: click Start bridge to reopen the window, or send a message; the next browser action reopens it.
  • Still undetected after the Portal address changed: a bridge started for the old address is holding the port and rejects this page. Stop it (end the efp-bridge process, or close the terminal it runs in) and click Start bridge again.
  • devtools_unavailable: Chrome refused its DevTools port. Check chrome://policy for RemoteDebuggingAllowed.
  • origin_denied / CORS error: the bridge was started for another Portal address. Restart it with --origin {{ portal_origin }}.
  • Windows SmartScreen may warn on first launch of efp-bridge.exe. Choose "More info" → "Run anyway".
  • The EFP browser window has its own logins. Sites protected by device-based sign-in may ask you to sign in there once.
